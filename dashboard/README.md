# Local aircraft dashboard

The dashboard reads `aircraft_snapshot_live.json` from the project root by default. Add `?demo=1` to the URL to preview the fully synthetic sample at `examples/aircraft_snapshot_demo.json`; add `&aircraft=D00001` to open a sample aircraft's details directly. Demo timestamps are rebased to the current time when loaded. The page refreshes every 1.5 seconds, draws a marker for each aircraft with a valid position, and connects the valid positions received so far as its path. It filters short-interval jumps that imply speeds above 1,200 knots and starts a separate line after a two-minute reception gap. The subscriber applies the same jump filter before saving positions. Select an aircraft in the list or on the map to see its available ADS-B details. The path shows received reports and does not estimate positions between them. The header reports a stale snapshot if no decoded message has updated the file for 15 seconds.

## Run it

### One-step startup

Copy `.flight-tracker.env.example` to `.flight-tracker.env` and set `FLIGHT_TRACKER_PYTHON` to the Python executable in your GNU Radio environment. Double-click `start_flight_tracker.command` in Finder. It starts the subscriber, GNU Radio flowgraph, and local web server, then opens the dashboard in your browser. Keep the Terminal window it opens running; press Control-C there to stop all three processes. Stop any manually started subscriber, flowgraph, or web server first. Logs are written to a timestamped folder under macOS's temporary directory.

### Manual startup

Keep three processes running in separate Terminal windows or tabs:

1. From the project directory, start the subscriber:

   ```sh
   cd "/path/to/Flight Path Tracking"
   source .flight-tracker.env
   "$FLIGHT_TRACKER_PYTHON" aircraft_stream.py
   ```

2. Run the generated flowgraph from its own Terminal tab so its output stays visible. From the project directory:

   ```sh
   "$FLIGHT_TRACKER_PYTHON" adsb_rx.py
   ```

   This launches the flowgraph's Qt window, but keeps its terminal output separate from GNU Radio Companion. Start the subscriber first so it is ready for the ZeroMQ messages. Open `adsb_rx_rtlsdr.grc` in Companion when you want to edit the blocks; regenerate `adsb_rx.py` there after changing the flowgraph.

3. In another Terminal window, serve the project directory:

   ```sh
   cd "/path/to/Flight Path Tracking"
   python3 -m http.server 8000
   ```

Open <http://localhost:8000/dashboard/> for the live snapshot or <http://localhost:8000/dashboard/?demo=1> for the synthetic demo. The map library and background map tiles load from the internet, while live aircraft data stays local.

Stop each process with Control-C in its Terminal window. After changing the subscriber's path filtering, restart it so it starts a fresh track history. The dashboard itself makes no connection to an aircraft data feed; it only reads the local snapshot generated by `aircraft_stream.py`.
